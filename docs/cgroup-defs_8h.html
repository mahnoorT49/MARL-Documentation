cgroup_root->flags

Enumeration Description: These flags control cgroup root behavior.

Enumerator
CGRP_ROOT_NOPREFIX 
CGRP_ROOT_XATTR 

mounted subsystems have no named prefix

CGRP_ROOT_NS_DELEGATE 

supports extended attributes Consider namespaces as delegation boundaries. If this flag is set, controller specific interface files in a namespace root aren't writeable from inside the namespace.

CGRP_ROOT_FAVOR_DYNMODS 

Reduce latencies on dynamic cgroup modifications such as task migrations and controller on/offs by disabling percpu operation on cgroup_threadgroup_rwsem. This makes hot path operations such as forks and exits into the slow path and more expensive.

Alleviate the contention between fork, exec, exit operations and writing to cgroup.procs by taking a per threadgroup rwsem instead of the global cgroup_threadgroup_rwsem. Fork and other operations from threads in different thread groups no longer contend with writing to cgroup.procs.

The static usage pattern of creating a cgroup, enabling controllers, and then seeding it with CLONE_INTO_CGROUP doesn't require write locking cgroup_threadgroup_rwsem and thus doesn't benefit from favordynmod.

CGRP_ROOT_CPUSET_V2_MODE 

Enable cpuset controller in v1 cgroup to use v2 behavior.

CGRP_ROOT_MEMORY_LOCAL_EVENTS 

Enable legacy local memory.events.

CGRP_ROOT_MEMORY_RECURSIVE_PROT 

Enable recursive subtree protection

CGRP_ROOT_MEMORY_HUGETLB_ACCOUNTING 

Enable hugetlb accounting for the memory controller.

CGRP_ROOT_PIDS_LOCAL_EVENTS 

Enable legacy local pids.events.

void cgroup_threadgroup_change_begin ( struct task_struct * tsk)
inlinestatic

cgroup_threadgroup_change_begin - threadgroup exclusion for cgroups @tsk: target task

Allows cgroup operations to synchronize against threadgroup changes using a global percpu_rw_semaphore and a per threadgroup rw_semaphore when favordynmods is on. See the comment above CGRP_ROOT_FAVOR_DYNMODS definition.

Function Description: Starts a read-side critical section for threadgroup changes. It acquires a global lock to prevent threadgroup modifications during cgroup operations. If the favordynmods feature is enabled, it also acquires a per-threadgroup lock to reduce contention and improve performance.
