Notify userspace when a cgroup is released, by running the configured release agent with the name of the cgroup (path relative to the root of cgroup file system) as the argument.

Most likely, this user command will try to rmdir this cgroup.

This races with the possibility that some other task will be attached to this cgroup before it is removed, or that some other user task will 'mkdir' a child cgroup of this cgroup. That's ok. The presumed 'rmdir' will fail quietly if this cgroup is no longer unused, and this cgroup will be reprieved from its death sentence, to continue to serve a useful existence. Next time it's released, we will get notified again, if it still has 'notify_on_release' set.

We don't bother to wait because the caller of this routine has no use for the exit status of the release agent task, so no sense holding our caller up for that.
